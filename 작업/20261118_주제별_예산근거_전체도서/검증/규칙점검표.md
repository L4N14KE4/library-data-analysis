## 2. 명세 정의를 따르는지 (특히 볼 것)

| 항목 | 따랐는가 | 근거 (파일·줄) |
|---|---|---|
| 입력 읽기 `utf-8-sig`, `dtype=str`, `keep_default_na=False` | 예 | 70 |
| 중앙값 ⌈n/2⌉번째 실제 값, 보간 없음 | 예 | 38~41 (`math.ceil(len(v)/2) - 1`). 17·19·22·162·163·165에서 쓴다 |
| 평균·비율: Fraction + ROUND_HALF_UP 정수 연산, `-0.00` 안 씀 | 예 | 22~30: k = ⌊100x + ½⌋ / 음수는 −⌊100\|x\| + ½⌋, k = 0이면 `0.00`. 172~183은 반올림 전 분수로 계산하고 f14(177)도 반올림 전 f12 − f13으로 구한다 |
| N3~N6 float, `Decimal(repr(float(x)))` 넷째 자리 | 예 | 104~107, 33~35. 이상치 판정(108)은 반올림 전 float로 한다 |
| 평균±3SD: 대상 전체 기준 하나, ddof=1, 경계와 같은 값은 이상치 아님 | 예 | 106 `np.std(arr, ddof=1)`, 108 `>`·`<` 엄격 부등호, 판정은 한 번 |
| 최대 잔여 반올림, 경계 동률이면 멈춤 | 예 | 49~66. R 범위 확인(57), 동률이면 멈춤(60~61), 합 확인(64) |
| 공동 순위 (승인 9번) | 예 | 44~46 `1 + (값이 더 큰 주제 수)`. 186~188 순위 지표는 f2·f7·f18·f1·f6의 반올림 전 값이다. 243~245에서 순위 식을 확인하고, '1~10 한 번씩' 실패는 공동 순위일 때라 멈추지 않는다(251·254). 이번 결과에는 동률이 없다 |

| 표·그림 행 순서 f0 내림차순, 동률이면 멈춤 | 예 | 257~260 |
| 그림 1: 유지 처리만, 2행 1열, figsize (12, 9), dpi 150, bbox tight | 예 | 329~331은 유지 값 f0·f2·f3만 쓴다. 333 `subplots(2, 1, figsize=(12, 9))`, 360 저장. 각주(351~355)는 명세 7-3 문구와 같고, f3이 모두 0 또는 1일 때만 마지막 문장을 넣는다(353~357) |

명세와 조금 다른 곳 (규칙 위반은 아님, 이번 결과에 영향 없음)
- 74 `df["주제분류명"].str.strip()`: 명세 2절은 '`주제분류명` 값 그대로'다. 앞뒤 공백이 붙은 주제 값이 있으면 분석은 그 값을 10개 안으로 받아들이고, 검증(공백을 지우지 않음)은 멈춘다. 이번 자료에서는 검증이 멈추지 않았으므로 공백이 붙은 값이 없고, 결과에도 차이가 없다.
- 88 `int(s)`: Python `int()`는 '+5'나 '1_0' 같은 글자도 정수로 받는다. 명세는 '정수로 바뀌지 않으면 멈춤'까지만 적었다. 검증은 `-?[0-9]+` 형식만 받도록 엄격하게 확인했고 멈추지 않았으므로, 이번 자료에는 그런 글자가 없다.

## 3. 분석 담당이 명세와 다르게 했다고 밝힌 4가지

| 항목 | 명세 위반인가 | 판단 근거 |
|---|---|---|
| (가) 표 CSV 머리줄에서 '(f0)' 같은 번호 꼬리를 뗌 | 위반 아님 | 명세 7-2는 '열: 주제분류명 \| 유지 권수(f0) \| …'처럼 열마다 어느 핵심 수치를 넣는지 괄호로 적었다. 머리줄 글자를 정하는 문장은 아니다. 2절 '주제 번호 j'도 '핵심 수치 번호에만 쓰며 표·그림과 관계없다'고 했으므로, 독자가 보는 표에 내부 번호를 빼는 쪽이 명세 취지에 맞다. 열 이름의 나머지 글자(예: '2023년 이후 구입 비율%', '시나리오 3 (대상 장서 구입가격 구성대로)')는 명세와 같다(296~317). 명세 문구는 두 가지로 읽힐 수 있다. 다음 판에서 계획 담당이 '머리줄 = 괄호 앞 글자'로 적어 두면 좋겠다 |
| (나) CSV를 utf-8-sig(BOM)로 저장 | 위반 아님 | 명세와 공통규칙 어디에도 출력 인코딩이 정해져 있지 않다. 원자료가 BOM 붙은 UTF-8이라 같은 형식이고, 엑셀에서 한글이 깨지지 않는 장점이 있다. 검증값.csv는 BOM 없는 UTF-8이다. 대조할 때는 `utf-8-sig`로 읽어 차이가 없었다 |
| (다) 처리 없는 값의 항목 이름을 '주제 + 수치 이름'으로 씀 | 위반 아님 (명세 그대로) | 명세 6-1: '처리가 없는 값은 처리를 빼고 쓴다'. 분석.py 227이 처리가 빈칸이면 빼고 이어 붙인다. 검증 쪽 이름도 같은 형식이다 |
| (라) 그림 1 두 칸 모두에 가로축 라벨 | 위반 아님 (명세 그대로) | 명세 7-3: '가로축(두 칸): `주제분류명`'. 두 칸 모두에 라벨을 다는 것이 명세대로다. 337·346 |

정리: 4가지 모두 명세 위반이 아니다. (다)·(라)는 명세와 다르게 한 것이 아니라 명세 그대로다.
